# skill 设计指南：外置 dsh 开发手册

> 结构权威。`skill/**` 的层级、命名、索引与引用、版本纪律、占位规则以本文为准；
> `AGENTS.md` 只记可执行硬约束，`src/facts.test.ts` 承载机器校验，计划真源是 mint。

## 0. 设计哲学

- **外置手册**：让 agent 不读 dsh（及上游）源码就能开发插件、定位问题——省 token、省时间、更准。
- **源码是最后手段**：手册给出 `deepseek-harness@<tag>` + `path`（可带 `:line`）作为兜底指针，并显式标注「最后手段，默认不读」。
- **懒加载**：只有 L0 随 skill 首载进 context；其余按问题下钻，下钻层数不设限。
- **纯手写**：不引入生成脚本，不做多 tag 机器复核；保鲜靠每页 pin + 版本页 + 人工重校（§6）。
- **只留一份**：中文主导，不写中英双份；能路由到官方内容就路由，不整段照抄。

## 2. 层级与懒加载

| 层  | 位置                                                                   | 职责                                                           | 首载 |
| --- | ---------------------------------------------------------------------- | -------------------------------------------------------------- | ---- |
| L0  | `skill/SKILL.md`                                                       | frontmatter + 使用协议 + 插件分类轴 + 三类入口路由 + L1 索引表 | 是   |
| L1  | `skill/references/<大类>/index.md`                                     | 大类索引：本类问题清单 → 类内页面                              | 否   |
| L2+ | `skill/references/<大类>/<页面>.md`（可继续下钻，每级自带 `index.md`） | 具体内容                                                       | 否   |

**L0 稳定性契约**：`SKILL.md` 不随 dsh 版本变动——不得出现上游路径、semver 字面量、`<repo>@<tag>`。新增大类时允许且必须加一行路由：那是设计内扩展，不是版本漂移。

页数预算（软约束，评审用）：L0 ≤ 120 行；L1 索引 ≤ 60 行；L2 内容页 ≤ 200 行，超了就再下钻一级。

## 3. 命名、索引与引用契约（= `src/facts.test.ts` 的断言）

命名：`skill/` 下除根 `SKILL.md` 外，目录名与文件名一律小写 kebab-case（`^[a-z0-9]+(-[a-z0-9]+)*$`）+ `.md`；页名表达问题，不用编号。

链接形态：站内链接统一写成相对 `skill/` 的路径（`references/…md`），禁止 `../` 与裸文件名。

- **索引边**：`SKILL.md` 必须**恰好**索引所有入口页（顶层 `references/*.md` + 每个 `references/<大类>/index.md`）且不带其它链接——L0 要保持薄与稳定，新增大类只加一行；每个 `index.md` 必须**至少**索引本目录下的 `*.md`（不含自身）与下一级目录的 `index.md`，允许额外的交叉引用（`references/` 目录本身由 `SKILL.md` 索引，不需要 `references/index.md`）。
- **引用边**：任何页面都可交叉引用任何页面，**允许成环**（整体是图不是树），但目标必须存在（无死链），且全图从 `SKILL.md` 可达。
- **回链**：每个非 `SKILL.md` 页面必须出现其父索引路径（顶层入口页的父是 `SKILL.md`）。
- **两段式引用语法**：
  - 直引：`先读 references/<路径>.md`——定位流程要求立刻读某个确定页面；
  - 间接引：`若涉及 <机制>，参见 references/<路径>.md`——先判断再下钻；跨大类引用主要走这条。

## 4. 版本维度

- **主干跨版本稳定**：架构页、契约页写层次与主干流转，不写会随版本改写的清单；清单进版本页。
- **内容页声明 pin**：每个**内容页**（`references/**` 下非 `index.md` 的页）在正文头部给出 `deepseek-harness@dsh-vX.Y.Z[-rc.N]`；本仓当前基准 `dsh-v0.2.0-rc.1`（与本机运行时一致）。索引页只做导航、不承载事实，不要求 pin。
- **版本页**：`references/dsh/versions/index.md` 列支持窗口与差分页命名 `references/dsh/versions/<from>-to-<to>.md`（回链本索引），形态是**反 CHANGELOG**：讲清从哪版到哪版、什么被改/删、历史插件为什么坏、升级要改什么。
- **不复制整页**：多版本共存时不复制成多份页面，只在受影响页加「版本差异」小节并指向版本页。
- **事实台账**：`skill/**` 每引用一条上游事实，必须在 `src/facts.test.ts` 登记一条 fact（`source` / `path` / 可选 `line` / `note`），反之亦然。

## 5. 演进步骤

- **新增一页**：放进所属大类目录；在最近的 `index.md` 加一行索引；页内写回链；头部写 pin；引用上游事实则登记 fact。
- **新增一个模块 / 内置 plugin 页**：`references/dsh/modules/<name>.md` 或 `references/dsh/plugins/<name>.md`（kebab-case），并在对应 `index.md` 索引；该册从占位转正式时删除占位标记。
- **新增一个大类**：建 `references/<大类>/index.md`，在 `SKILL.md` 路由表与 L1 索引表各加一行，并在本文 §1 表补一行。
- **新增一个 dsh 版本**：写 `references/dsh/versions/<from>-to-<to>.md`（反 CHANGELOG）并在 `versions/index.md` 索引；受影响页加「版本差异」小节、重校并更新 pin；按 §6 复核。

## 6. 保鲜纪律（纯手写）

- 事实台账的自动复核**一次只覆盖一个本地 checkout 版本**：`3rdp/deepseek-harness` 停在哪个 tag，就只复核 pin 到该 tag 的 fact；其它版本的 fact 跳过且不失败（`3rdp/` 缺失时全部跳过——那是测试 / 生产常态）。
- 历史差分只能人工对照：用 `git -C 3rdp/deepseek-harness show <tag>:<path>` 只读查看，**不切换工作树**。
- 升级基准版本：`git -C 3rdp/deepseek-harness checkout <新 tag>` → 重校 pin 到旧 tag 的页面 → 更新 pin → 写差分页。
- 想要自动多版本复核，需要扩展 `src/facts.test.ts` 的 `REFERENCES`（一个 repo 对应多个 checkout）；当前明确不做。

## 7. 占位纪律

- 尚未填充的索引写成占位，固定标记：

  `> 占位｜归属：<大类>｜填充：plan #<id>`

- 占位页要写清：本页回答什么、条目命名契约、由哪个 plan 填充。
- 填充时删除占位标记——断言要求「含『占位』的行必须带 plan 号」。

## 9. 源码指针写法

兜底指针统一写成 `deepseek-harness@dsh-v<tag>` + `path`（可带 `:line`），同段注明用途与「最后手段，默认不读」。指针里的路径同样是 fact：登记进 `src/facts.test.ts`。
