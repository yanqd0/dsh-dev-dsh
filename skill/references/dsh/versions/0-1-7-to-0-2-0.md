# 0.1.7 → 0.2.0 反 CHANGELOG：从 0.1.7 线升级或排障

本文是 `references/dsh/versions/index.md` 的子页。**默认不读**：只有「插件从 0.1.7 线升到 0.2.0」或「定位
0.1.7 时代的插件问题」、且确实涉及版本差异时才读。0.1.5 线另见 `references/dsh/versions/0-1-5-to-0-2-0.md`。

上游事实出处：`deepseek-harness@dsh-v0.2.0-rc.2`（对照 `dsh-v0.1.7-rc.2`）；行号随版本漂移，由
`src/facts.test.ts` 复核。

## 1. 改了什么 / 删了什么

**默认组合不再带 Schedule。** `packages/bundle/web-app/cordis.patch.yml` 在 0.1.7-rc.2 里以 `disabled: true`
挂着 `time-context`（:121）、`schedule`（:125）、`ui-schedule`（:370）三行；0.2.0 起这三行不在该文件里，改由
`@deepseek-ai/dsh-experimental-schedule-bundle`（`packages/experimental/schedule-bundle`）插入。该包进入
`OPTIONAL_BUNDLES`，随每个安装携带、默认关闭。原因与取舍见
`.agents/notes/implemented/architecture/2026-09-24-schedule-opt-in-optional-bundle.zh.md`（§Decision）。

**遥测与 OTel 扩容。** base 层新增 `otel` 行（`packages/bundle/base/cordis.patch.yml:188`，包是
`packages/telemetry/otel`）；`session-telemetry-otel` 的导出端点换成 `dsh-otel-collector.deepseeksvc.com`，新增
`maxRequestBytes: 4000000`，批量语义从「单批排空」改为**按字节分批 + 串行发送**（每次请求 1s 传输超时，
外加 1.5s watchdog）。叙述见 `docs/subsystems/otel.zh.md` 与决策记录
`.agents/notes/implemented/architecture/2026-09-25-session-log-otel-byte-limits.zh.md`。

**新增三行。** 两条 desktop-only：`desktop-product-telemetry`
（`packages/bundle/web-app/cordis.patch.yml:45`）与 `product-analytics`（:57），用
`disabled: !!js ctx.get('profileContext')?.name !== 'desktop'` 做部署门；一条客户端行
`ui-settings-session-log`（:396）。

**creator skill 从 3 个增至 4 个。** 新增 `agent-experience`（位于 `packages/preset/agent-preset/skills`）。
官方 Creator 模式自带内容的边界见 `references/develop/skill-plugins.md`，本手册不重复。

**官方升级指南制度落地。** 上游在本窗口加入 `docs/upgrade-guide/**` 的结构、流程与门禁，并为 0.1.7-rc.2 记了
两条。它与本页互补：指南写给 profile 使用者（怎么打开开关），本页写给插件作者（哪些写法会坏）。

**没有变的（重要）。** 会话格式仍是 **V4**；`dsh.bundle` / `dsh.client` 清单、`packages/client/modules`、
`packages/skill`、`packages/core/tools`、`packages/AGENTS.md` 与 `vendor/cordis` / `vendor/loader` 等
vendored 包在本窗口都没有改动。⟹ 「换成 0.2.0 就跑不起来」通常不是这批契约造成的，先按
`references/dogfood/runtime-triage.md` 定位。

**客户端 UI 大量变更。** `packages/client` 下的界面改动很多，但本手册在 0.1.0 阶段不覆盖客户端构建；界面行为
差异优先怀疑客户端包版本，而不是宿主契约。

## 2. 历史插件为什么坏

- **按 id 开 Schedule 的配置**：`cordis.patch.yml` 或 `--patch` 里写 `- id: schedule`（配 `disabled: false`）
  的人，升级后 loader 只报 `patch: entry schedule not found`（`time-context`、`ui-schedule` 同理）。**警告不是
  失败**，但 `schedule_*` 工具、Session 提醒目录、自动化任务页一起消失，已存提醒不再投递。
- **自带 Schedule 行的 bundle**：与 web-app 组合撞同 id 时，`insert:` 组合出的列表按 id 收敛（last-wins）——
  谁在最后谁生效，不报错。
- **观测遥测的部署**：显式设了 `DSH_TELEMETRY_OTLP_URL` 或按旧域开网络白名单的，导出会静默失败；新的串行 +
  按字节分批语义也改变了吞吐与退出时的排空预算。
- **逐步操作**：官方指南 `docs/upgrade-guide/v0.1.7-rc.2/schedule-optional-bundle/guide.zh.md` 的 §迁移 给出
  了开关、清理与确认步骤。

## 3. 升级要动哪些文件与字段

| 要动的东西                                                     | 怎么改                                                                                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `$DSH_HOME/profiles/<p>/package.json` 的 `dsh.profile.bundles` | 追加 `@deepseek-ai/dsh-experimental-schedule-bundle`（插件管理页打开「自动化任务」等价）；手动维护的 profile 自己加这一条      |
| `$DSH_HOME/profiles/<p>/cordis.patch.yml`                      | 删掉只写 `disabled: false` 的三条覆盖项；**保留**设置其它字段（如 `deliveryHistoryDays`）的覆盖项——bundle 插入行后它们重新生效 |
| 遥测配置                                                       | 显式 `DSH_TELEMETRY_OTLP_URL` 改到新域；按「串行 + 按字节分批 + 1.5s watchdog」重估预算                                        |
| peer / dev 依赖                                                | 与 `@deepseek-ai/dsh*` 对齐到 0.2.0 线；本窗口无 API 变更，属例行对齐                                                          |

组合、层序与「同一行后应用者胜」见 `references/dsh/composition-and-boot.md`；安装与 reconcile 的失败面见
`references/develop/build-and-pitfalls.md`。

## 4. 哪些写法静默失效

1. 按 id 覆盖一个**已经不在组合里**的行：只留一条 `patch: entry … not found` 警告。
2. 「行留在组合里、用 `disabled: false` 打开」这套 0.1.7 的开关法——行已经不在了。
3. 假设 `dsh web` 默认带 Schedule（工具 schema、逐步时钟消息、自动化页面都没了）。
4. 依赖旧 OTLP 域、或依赖旧的单批排空预算的部署。
5. 对同 id `insert:` 的预期：组合层与你自己的 patch 层之间是 last-wins，不是报错。

## 5. 复核手法（只读）

拿本地 dsh checkout 逐条核对，**不切换工作树**：

```bash
git -C <checkout> show dsh-v0.1.7-rc.2:packages/bundle/web-app/cordis.patch.yml | grep -n 'id: schedule'
git -C <checkout> diff dsh-v0.1.7-rc.2 dsh-v0.2.0-rc.2 -- packages/bundle packages/telemetry
```

第二行能一次看到「rows 移出 + otel 行与端点变化」这两类改动；本页每条结论都能在它的输出里对上。
