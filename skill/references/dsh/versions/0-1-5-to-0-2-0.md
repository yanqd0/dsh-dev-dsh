## 1. 头部结论：改了什么

**会话格式 V3 → V4。** `SESSION_FORMAT_VERSION` 在 `dsh-v0.1.5-rc.3` 是 **3**、在 `dsh-v0.1.7-rc.2` 是 **4**
（常量在 `packages/core/session`）。配套的持久化变更记录体系 `docs/persistence-changes` 在 0.1.5 上**还不存在**
（0 个文件），0.1.7 上已有 161 个文件、其中 40 个中文页，含索引、定稿与历史格式说明
（如 `docs/persistence-changes/historical-formats/README.zh.md`）。

**包组重排。** 按 `packages/README.zh.md` 的分组口径，本段移除了 `code-runtime`、`e2b` 两个组；出现了
`browser-use`、`computer-use`、`deliverables`、`document`、`ptc-runtime`、`ssh`（`telemetry` 属
0.1.7 → 0.2.0 窗口，见 0.1.7 页）。

## 2. 为什么坏（头部）

- **格式版本是硬门禁**：V3 与 V4 互不兼容。写 / 读会话日志、投影消息、按事件类型分支的插件在这条线上必然要动。
  迁移链与「相邻版本」规则见 `references/dsh/persistence-and-format.md` 与 `references/dsh/session-log.md`；
  上游权威是 `docs/subsystems/session.zh.md` 与 `docs/cookbook/adding-a-session-format-version.zh.md`。
- **按包组或路径硬编码**的定位方式失效：组被删或被拆分后，包名与错误串都会变。

## 3. 升级要动什么（头部）

1. 先完成 V3 → V4 的事件词汇与投影适配（迁移链、相邻转换与不可变代际见持久化页）。
2. 再按 `references/dsh/versions/0-1-7-to-0-2-0.md` 处理 0.1.7 → 0.2.0 的组合面（Schedule、遥测）。
3. 用 `pnpm test` 加真实 profile 启动复核——类型编译通过**不**代表日志能读。

## 4. 静默失效（头部）

1. 用「事件类型 / 字段存不存在」判断兼容：权威是 `SESSION_FORMAT_VERSION` 与持久化变更记录，不是类型提示。
2. 依赖已删组（`code-runtime`、`e2b`）的路径或包名。
3. 假设 0.1.5 时代的 profile 组合与 0.2.0 的默认组合一致（Schedule 已移出，见 0.1.7 页）。
