# dsh-dev-dsh

面向**仓外**（out-of-tree）DSH 插件仓库的外置开发手册：插件有自己的仓库、自己的工具链，
发布到 npm，而不是放进 `deepseek-harness` monorepo。

**目标**：不读 dsh 源码就能开发插件、定位问题。手册先给结论与指针；源码是最后手段——需要兜底时
页内会给出 `deepseek-harness@<tag>` 加具体路径，默认不推荐读取。

## 怎么用（懒加载协议）

1. 本页是唯一随 skill 首载进 context 的内容：定位、分类轴、路由；其它页都按需加载。
2. 按问题在下表选一个大类入口，读它的 `index.md`，再按索引下钻。
3. 引用是**图不是树**：跨类直引（`先读 …`）出现时按指示去读；间接引（`若涉及 …，参见 …`）先自己判断
   是否相关，再决定读不读。
4. 只在手册明确缺这一块、且工作确实卡住时，才按页内指针去读上游源码。

## 插件分类轴（同一轴贯穿开发与定位）

dsh 一切皆插件，但不同分类接入的层、可用的工程面、会碰到的失败面完全不同：

- **新增工具（tool）**：向模型暴露能力，接工具注册表与 schema。
- **外围扩展**：挂在既有服务或事件上（策略、适配器、守卫、后台任务）。
- **harness 核心替换**：替换核心服务或驱动器（如 agent loop、模型适配器）——与官方包同权。
- **web UI / 客户端插件**：客户端 bundle 与插槽 / 路由。
- **skill 型**：随包分发知识，并按需同步安装。
- **preset / 组合包**：装配一组插件与配置层。
- **MCP / hooks**：接入外部能力，或桥接其它 agent。

每个分类的流程、最小示例与失败面见 `references/develop/index.md`。

## 边界

- 只覆盖**宿主面**（host-side）仓外插件工程与排障；客户端 / UI 插件的构建 preset 不在当前承诺范围内。
- 官方已经在 profile 内覆盖的开发方式（creator 自带 skill、运行时 API 探针、插件管理）不在本手册重复，
  只做路由——官方能力表见 dsh 本体大类的架构主干。
- 本手册是仓外工程的补充，不替代上游文档；能路由就路由，避免随版本腐烂。
